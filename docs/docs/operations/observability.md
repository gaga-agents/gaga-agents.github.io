# 可观测性与持续治理

平台治理形成“观察 → 分析 → 优化 → 重新发布”的闭环。观测对象既包括 Kubernetes 和微服务，也包括智能体执行过程。

![智能体持续治理闭环](/img/diagrams/governance-loop.svg)

![平台日志与调用链监控](/img/screenshots/observability.webp)

## 两类观测

### 智能体层

- 用户、项目、智能体、会话和任务标识；
- Prompt/模型/知识/工具版本；
- 节点轨迹、工具参数、召回证据与错误；
- Token、调用次数、延迟和成本；
- 最终状态、终止原因和用户反馈。

### 平台层

- Pod、CPU、内存、磁盘和队列积压；
- 服务注册、健康检查和 Gateway 路由；
- HTTP/Kafka/MongoDB/Milvus/Neo4j 调用错误；
- 分布式调用链和关联日志；
- 发布版本、实例数量和异常时间线。

## 排障顺序

1. 用任务 ID 定位失败执行。
2. 判断问题属于输入、模型、知识、工具、编排还是平台基础设施。
3. 沿调用链找到第一个异常节点，而不是最后一个报错页面。
4. 对照同版本成功请求，比较参数、依赖和资源状态。
5. 修复后用原失败样例回归，再构建并发布新版本。

## 最小告警集

生产环境至少关注：Gateway 5xx 和延迟、关键服务健康、Pod 重启、Kafka 积压、数据库连接、知识处理失败率、模型 429/超时、沙箱超时、单任务 Token/成本异常。
