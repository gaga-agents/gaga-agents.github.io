# 设计多智能体编排

编排用于把已经能够独立工作的智能体和确定性处理节点组织成可验证的流程。平台支持开始/结束、Agent 任务、模型、工具、代码、API、条件、并行、循环、迭代、转换、合并、变量和子流程等节点。

![多智能体编排设计与验证流程](/img/diagrams/orchestration-flow.svg)

![编排编辑器与调试结果](/img/screenshots/orchestration-editor.webp)

## 设计流程

1. **复用现有智能体**：先确保每个角色可以独立调试通过。
2. **定义输入输出契约**：为每个节点明确输入变量、输出字段和错误结构。
3. **设计 DAG**：先画主成功路径，再补条件、失败和重试路径。
4. **逐段调试**：从两个节点开始，确认变量映射后再扩展。
5. **验证并构建**：使用固定样例检查执行顺序、并行合并和终止条件。

## 节点选择

![任务编排与执行控制](/img/diagrams/task-orchestration.svg)

| 需求 | 优先节点 |
| --- | --- |
| 调用一个专业智能体 | Agent Task / Sub-agent |
| 确定性字段处理 | Transform / Variable Set |
| 根据字段走不同路径 | Condition / Switch |
| 多任务互不依赖 | Parallel + Join |
| 有界重复处理集合 | Iteration |
| 根据条件重复 | Loop，必须设置终止条件 |
| 复用稳定流程 | Subflow |
| 外部人工确认 | Approval |

## 变量与契约

不要让下游节点从一大段自然语言中猜字段。优先输出结构化对象，并在连线处明确映射。编排失败时先检查上游真实输出，再检查变量路径、类型和空值处理。

## 复杂度控制

如果一个流程难以在一张画布中解释，应把稳定片段抽成子流程。并行只用于互不依赖的任务；循环必须有最大次数、超时和终止条件；高风险写操作应设置显式审批或确定性检查。
