# A2A 与协作模式

A2A（Agent-to-Agent）让智能体以能力和任务契约相互协作。它适合角色边界清楚、可以独立演进的智能体，不等同于把多个 Prompt 随意串联。

![A2A 自协作示例](/img/screenshots/a2a-collaboration.webp)

## A2A 契约应包含

- 智能体身份、能力和适用范围；
- 可接受的任务输入和预期输出；
- 会话、项目和调用方身份；
- 超时、取消、失败和重试语义；
- 执行状态与产物访问方式；
- 版本和兼容策略。

## 显式编排还是 A2A

| 情况 | 建议 |
| --- | --- |
| 流程顺序、分支和审批必须稳定可见 | 使用显式编排 |
| 多个智能体属于独立服务，运行时协商任务 | 使用 A2A |
| 既要固定主流程，又要在节点内委派专业任务 | 编排中调用 A2A 智能体 |
| 单个智能体内简单工具调用 | 不必引入 A2A |

## 调试重点

除了最终答案，还要记录请求方、接收方、任务 ID、状态变化、重试和产物引用。跨智能体传递的内容应遵循项目权限；不要因为调用链变长就丢失用户和项目上下文。
