# 使用可视化编排

智能体编排通过可视化工作流组织多个智能体和控制节点，用于定义任务如何接收输入、分支处理、汇总结果并返回回答。

## 使用前提

开始前请确认：

- 已创建并选择一个项目；
- 已创建本流程需要调用的智能体，并完成模型和 Prompt 配置；
- 当前账号具有该项目的编辑权限。

## 1. 新建编排

进入 **智能体编排** 页面，点击右上角的 **新建编排**。

<img src="/img/orchestration/editor/create-orchestration-form.png"
     alt="新建编排表单"
     width="80%" />

- **编排标识符**：系统内部使用的唯一标识，建议使用英文小写字母、数字和下划线，例如 `api_workflow`。
- **编排显示名称**：展示给用户的名称。
- **描述**：简要说明该编排的用途。
- **调试预设 Prompt**：配置测试页中的快捷输入按钮，便于重复执行常用的验收任务。

点击 **确定** 后，系统会创建一个空编排并进入编辑界面。

<img src="/img/orchestration/editor/empty-orchestration-editor.png"
     alt="空编排编辑界面"
     width="100%" />

空编排尚不满足执行条件，因此会显示“暂时不能执行”。保存工作流时，系统会重新编译并列出具体错误。一个可执行工作流至少需要满足以下要求：

- 必须且只能包含一个开始节点和一个结束节点；开始节点不能有入边，结束节点不能有出边。
- 所有节点和连线必须有效，每个节点都能从开始节点到达，结束节点也必须可达。
- 外层流程不能形成循环；需要循环时应使用循环或迭代节点。
- 智能体任务节点必须绑定当前项目中已正确配置且可用的智能体。

## 2. 编辑工作流

页面顶部显示编排名称、节点数、连线数和当前编译状态，并提供撤销、重做、导入、导出、允许执行和保存操作。

关闭 **允许执行** 后，该编排即使已经通过编译也不会接受新的执行请求。**最大并发数** 限制单次流程中可同时运行的节点数量，默认值为 `8`，可设置为 `1`～`128`。

修改工作流后，页面会显示“未保存修改”。点击 **保存** 后，系统会保存当前图并重新进行编译检查。

**导出** 会下载包含节点、连线和流程设置的 JSON 文件；**导入** 可读取相同结构的 JSON 文件并替换当前画布内容。导入后仍需点击 **保存**。

左侧为节点库。将节点拖到右侧画布即可添加；从节点端口拖出连线可以连接节点；点击节点可在右侧配置面板中编辑。

## 3. 配置节点

### 开始节点

<img src="/img/orchestration/editor/start-node-config.png"
     alt="开始节点配置"
     width="80%" />

开始节点是工作流的唯一入口，用于定义运行时需要接收的输入变量。可以为变量设置名称、类型、是否必填、默认值和说明。测试时，聊天文本和工作空间文件会从该节点进入流程；缺少必填变量时，流程不会启动。

### 智能体任务节点

<img src="/img/orchestration/editor/agent-task-node-config.png"
     alt="智能体任务节点配置"
     width="80%" />

智能体任务节点用于调用当前项目中已配置的智能体。选择智能体后，在 **智能体指令** 中填写该节点要执行的任务。如果不指定输入内容，默认使用上游节点的主要输出。

可以通过变量选择器插入开始节点变量、全局变量或上游节点的输出。变量会以 `{{ 变量路径 }}` 的形式写入指令，并在运行时替换为实际值。

<img src="/img/orchestration/editor/open-variable-selector.png"
     alt="打开变量选择器"
     width="80%" />

<img src="/img/orchestration/editor/select-variable-path.png"
     alt="选择变量路径"
     width="80%" />

### 条件节点

<img src="/img/orchestration/editor/condition-node-config.png"
     alt="条件节点配置"
     width="80%" />

条件节点根据配置的判断规则选择 `true` 或 `false` 输出端口。可以组合多条条件，并选择满足全部条件（AND）或任一条件（OR）；条件两侧可使用变量，也可与固定值比较。后续节点应连接到对应的输出端口。

### 汇聚节点

<img src="/img/orchestration/editor/join-node-config.png"
     alt="汇聚节点配置"
     width="80%" />

汇聚节点将多个上游分支重新合并。输入分支名称应与节点输入端口一一对应。**继续条件** 可选择等待所有分支完成，或任一分支完成后继续；**结果形式** 可按分支名称组成对象、组成列表、取第一个结果，或选择出现次数最多的结果。

### 审批节点

<img src="/img/orchestration/editor/approval-node-config.png"
     alt="审批节点配置"
     width="80%" />

审批节点会暂停流程并等待人工选择 **通过** 或 **拒绝**，随后分别从 `approved` 或 `rejected` 端口继续。可以设置等待提示和需要展示的审批上下文；开启 **自动通过** 或预设审批结果后，节点不会等待人工操作。

### 回答节点

<img src="/img/orchestration/editor/answer-node-config.png"
     alt="回答节点配置"
     width="80%" />

回答节点用于生成展示给用户的文本内容。回答内容支持插入变量和上游节点输出；如果引用的是对象或列表，运行时会将其转换为可展示的文本。回答节点输出后，流程仍可继续连接其他节点。

### 结束节点

<img src="/img/orchestration/editor/end-node-config.png"
     alt="结束节点配置"
     width="80%" />

结束节点是工作流的唯一出口，用于结束本次执行，并将接收到的主要结果作为流程最终结果返回。结束节点只能有入边，不能再连接后续节点。

## 4. 保存并检查工作流

完成节点配置和连线后，点击 **保存**。当工作流通过编译时，页面会显示“流程可以执行”；如果仍处于编辑状态，应按照页面列出的编译错误继续修正。

<img src="/img/orchestration/editor/executable-workflow.png"
     alt="可执行的工作流"
     width="100%" />

## 5. 运行测试

返回智能体编排列表，点击对应编排的 **测试** 按钮进入测试界面。输入任务后发送，即可从开始节点触发工作流。

<img src="/img/orchestration/editor/orchestration-test-page.png"
     alt="编排测试界面"
     width="100%" />

执行过程中，页面会展示节点状态和最终回答。如果流程进入审批节点，可以在当前执行中选择通过或拒绝。

<img src="/img/orchestration/editor/orchestration-execution-result.png"
     alt="编排执行结果"
     width="80%" />

点击下方的 **运行流程**，可以查看本次执行经过的节点。选择节点后，可进一步查看其输入、输出和 Trace 信息。

<img src="/img/orchestration/editor/execution-flow-details.png"
     alt="运行流程详情"
     width="80%" />

## 6. 查看历史会话

切换到 **历史** 页签，可以查看已有会话及其执行次数。选择 **继续** 可恢复对应会话的上下文并继续测试。

<img src="/img/orchestration/editor/conversation-history.png"
     alt="会话历史"
     width="100%" />
