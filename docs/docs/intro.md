# 嘎嘎鸭智能体快速开发部署平台

**gagaduck-agents-platform** 是面向智能体完整生命周期的快速开发与部署平台。它把模型、知识库、Skills、记忆、规划、单智能体、多智能体编排、构建发布和运行观测放在同一个项目空间中，目标是缩短“可以演示的原型”到“可以交付和持续维护的系统”之间的距离。

平台不是一个只负责聊天的模型界面，也不是单独的工作流画布。一个可交付的智能体至少要同时处理状态、任务、知识、工具和治理五类工程问题；平台围绕这五类问题提供统一的资源管理与运行边界。

![平台需要解决的五类问题](/img/diagrams/five-problem-domains.svg)

## 平台解决什么问题

| 原型阶段常见做法 | 进入真实环境后的问题 | 平台提供的能力 |
| --- | --- | --- |
| 在代码中直接调用一个模型 | 模型、密钥、参数和成本分散 | LLM 与机理模型统一配置 |
| 把上下文拼进一段 Prompt | 会话变长后状态不可控 | 会话、记忆和工作空间隔离 |
| 在模型回答前临时检索文档 | 数据处理与召回质量难以追踪 | 文档处理、向量检索、图谱与重排 |
| 让模型直接执行外部操作 | 参数、权限、超时和副作用难以控制 | Skills 注册、校验、代理与沙箱执行 |
| 靠日志猜测执行过程 | 无法定位节点、工具或模型故障 | 轨迹、调用链、Token/成本与服务健康观测 |

## 核心对象

- **项目**：用户、资源和智能体的治理边界。LLM、工具、知识库、智能体和编排都归属于项目。
- **基础资源**：LLM、机理模型、云平台 Skills、外部 Skills 与知识库。
- **智能体**：由 Prompt、模型、工具、知识、记忆、规划策略和运行参数组成的可执行单元。
- **编排**：通过节点、变量、条件、并行、循环、子流程和 Agent 任务组织复杂协作。
- **构建产物**：经过调试确认后生成、部署并纳入版本管理的智能体或编排应用。

## 典型场景

1. **知识型智能体**：围绕内部文档或领域资料进行检索、引用和问答。
2. **工具型智能体**：调用 API、Skills、代码或机理模型完成查询、计算与操作。
3. **流程型智能体**：用条件、并行和循环把确定性流程与模型判断结合。
4. **多智能体协作**：复用已有智能体，通过 DAG 或 A2A 协议拆分与协同任务。
5. **可治理的生产服务**：对执行轨迹、调用链、异常、成本和服务健康持续观测。
