# 快速启动：完成首个智能体

本教程用一个不依赖知识库和外部工具的“需求澄清助手”走通最短链路。完成后，再按场景增加 Skills、知识库、记忆或编排。

## 目标与前提

完成后你将拥有一个已连接 LLM、能够按结构澄清需求、通过调试并生成构建记录的智能体。

开始前确认：

- 已经[创建并选择项目](./first-project.md)；
- 拥有可用的模型端点、模型名和 API Key；
- 平台后端可以访问模型提供方。

## 1. 配置 LLM

进入 **基础配置 → LLM 配置**，新建配置并填写提供方、服务端点、模型标识和凭据。保存后先执行连接测试。

连接失败时，不要进入 Prompt 调试。先检查端点、模型名、密钥权限、网络代理、证书和配额。

## 2. 创建智能体

进入 **智能体管理 → 智能体配置**，选择 **创建智能体**：

- 名称：`需求澄清助手`
- 说明：`将模糊需求整理为目标、输入、约束、验收标准和待确认项`
- 类型/模板：选择通用或空白模板

## 3. 配置最小可用能力

在配置页完成：

1. **LLM**：选择刚才验证成功的模型配置。
2. **Prompt**：写清角色、任务、约束和输出格式。
3. **规划**：首个示例使用简单策略；任务需要工具循环时再选择 ReAct，需要先分解再执行时使用 Plan-and-Execute。
4. **高级参数**：先保持保守的温度和输出长度，避免同时调整过多变量。

可使用以下 Prompt 起步：

```text
你是需求澄清助手。你的任务不是直接给出实现方案，而是把用户输入整理为：
1. 业务目标
2. 已知输入
3. 约束条件
4. 可验证的验收标准
5. 仍需确认的问题

如果信息不足，明确标记“待确认”，不要编造事实。
```

## 4. 调试三个层次

依次输入：

1. **正常样例**：给出一个相对完整的需求，检查结构是否稳定。
2. **缺失样例**：只说“帮我做一个智能体”，检查是否提出必要问题。
3. **边界样例**：要求它跳过澄清直接编造数据，检查约束是否仍然生效。

除了最终回复，还要查看运行状态、错误信息、模型调用和执行轨迹。记录失败输入，作为之后的回归样例。

## 5. 构建交付版本

调试通过后进入 **智能体构建**，为本次构建填写可读的版本说明，例如“首版：结构化需求澄清，无外部工具”。发起构建后确认状态成功，并保留对应的智能体配置版本。
