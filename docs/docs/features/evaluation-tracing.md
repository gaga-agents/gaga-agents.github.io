# 评测、追踪与回归

智能体质量需要同时观察“答得对不对”和“系统怎么做到的”。平台的执行记录、SSE 事件、服务日志和 SkyWalking 追踪分别回答不同问题。

## 三层证据

| 层级 | 回答的问题 | 典型字段 |
| --- | --- | --- |
| 结果评测 | 最终答案是否满足业务标准 | correctness、groundedness、格式 |
| 执行追踪 | 哪一步、哪个工具或模型导致结果 | execution_id、step_id、tool、duration |
| 系统观测 | 是否存在服务、队列或资源瓶颈 | health、latency、error、queue |

## 最小回归集

至少包含正常请求、歧义请求、无权限请求、无结果检索、工具失败、超时、长上下文和多模态边界样例。为每条样例记录期望属性，不要强制所有合法答案都等于一段固定文本。

## 成本与延迟

按执行记录模型调用次数、Token、工具次数、检索耗时、总耗时和重试次数。一次“回答正确但延迟过高”的运行，仍然需要工程优化；一次“很快但没有证据”的运行，也不能作为上线依据。

## 回归流程

保存版本化配置 → 重放样例 → 比较结果和追踪 → 定位责任层 → 修改一个变量 → 再跑全量回归 → 记录发布证据。这样才能判断是 Prompt、模型、知识库、工具还是编排变化带来了改进。
