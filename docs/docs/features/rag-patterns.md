# RAG 集成方式比较

RAG 不是单一组件，而是读取、分块、Embedding、存储、检索、重排和回答约束组成的链路。当前知识库服务提供 VectorRAG 与 GraphRAG 类型，智能体配置还可以把知识库暴露为工具，由 Agentic Loop 决定何时调用。

## 集成方式比较

| 集成方式 | 描述 | 优点 | 缺点 | 适合场景 |
| --- | --- | --- | --- | --- |
| 智能体自主控制 | 将知识检索暴露为工具，由智能体决定是否查询和如何改写关键词 | 灵活；可多轮查询；避免无关检索 | 依赖模型工具调用与查询改写能力；成本不稳定 | 开放问答、需要多跳检索的任务 |
| 通用固定方式 | 每次回复前固定检索，并把结果注入 Prompt | 实现简单；行为可预测；模型要求低 | 每次都查询；可能增加延迟和无关上下文 | FAQ、固定领域问答、低复杂度流程 |
| VectorRAG | Embedding 后按相似度检索文本块，可选重排和阈值 | 语义匹配直观；适合段落级知识 | 对精确实体关系和跨文档推理有限 | 产品文档、制度、说明书 |
| GraphRAG | 抽取实体关系，进行局部/全局图搜索并关联文本块 | 擅长关系、实体和跨文档结构 | 建图成本高；抽取质量影响结果 | 组织关系、设备拓扑、复杂领域知识 |

## 建议的决策顺序

先用 VectorRAG 建立可评测基线；当问题明显依赖实体关系或社区摘要时再引入 GraphRAG；只有在固定检索无法覆盖问题变化时，才把检索交给智能体自主控制。

## 评测指标

分别记录召回命中率、证据相关性、答案引用正确性、平均检索耗时、Token 增量和无关查询比例。不要只看最终答案是否流畅。
