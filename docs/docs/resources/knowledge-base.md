# 知识库

知识库把文档转换为可检索的证据，并在运行时向智能体提供与问题相关的上下文。平台链路覆盖文档解析、切分、Embedding、向量索引、可选的实体关系抽取、召回和 Reranker。

## 建库流程

1. 在当前项目进入 **知识库**，创建知识库并写清业务范围。
2. 上传 PDF、Word、TXT 或 Markdown 等文档。
3. 选择解析与切分策略；按标题、段落或语义边界切分通常优于固定字符硬切。
4. 选择 Embedding 模型并构建向量索引。
5. 需要关系推理时启用实体抽取和图谱处理。
6. 等待任务完成，检查失败文档、Chunk 数量和索引状态。
7. 使用一组真实问题独立测试召回，再绑定智能体。

## 三种检索路径

- **VectorRAG**：用语义相似度召回文本块，适合事实查找和近义表达。
- **GraphRAG**：沿实体关系发现跨文档联系，适合关系与路径问题。
- **AgenticRAG**：由智能体根据任务多轮改写查询、选择知识源或组合工具，能力更强但成本和不确定性更高。

详细的决策矩阵见[RAG 集成方式比较](../features/rag-patterns.md)；如果需要图片、图表或视觉问答，先阅读[多模态知识库设计](../features/multimodal-knowledge.md)。

## 质量检查

不要只问“最终答案对不对”，还要检查：

- 正确文档是否成功解析；
- 关键语义是否被切散或标题上下文是否丢失；
- Top-K 中是否出现真正相关的 Chunk；
- Reranker 是否把强证据排到前面；
- 回答是否能区分知识证据与模型推断；
- 文档更新后旧索引是否被替换。

## 项目隔离

知识文件、索引和引用关系应归属于项目。跨项目共享知识时需要明确授权与更新责任，不能仅凭向量库中“能够搜到”就视为允许访问。
