# 模型资源

平台把通用大语言模型与领域机理模型作为两类资源管理：LLM 负责理解、生成与规划，机理模型负责确定性的专业计算或仿真。二者都应先完成独立验证，再被智能体或编排引用。

## LLM 配置

进入 **基础配置 → LLM 配置** 创建模型连接。至少明确：

| 字段 | 说明 | 常见问题 |
| --- | --- | --- |
| 提供方/协议 | 模型服务的兼容协议 | 把网页地址误填为 API Base URL |
| 服务端点 | 平台后端可访问的地址 | 容器内的 `localhost` 指向容器自身 |
| 模型标识 | 服务端实际暴露的模型名 | 展示名与 API 模型名不一致 |
| 凭据 | API Key、Token 或其他认证 | 权限、配额、过期和 Secret 泄露 |
| 默认参数 | 温度、最大输出、超时等 | 调试时同时改变过多参数 |

保存后执行连接测试，并记录模型提供方返回的原始错误。HTTP 401/403 通常指向凭据，404 指向端点或模型名，429 指向限流/配额，超时则需要检查网络与推理时延。

## 机理模型

机理模型通常由明确的输入、输出和运行环境组成。注册时应提供：

- 稳定的模型标识与版本；
- JSON Schema 等可校验的输入输出契约；
- 运行镜像、入口或调用地址；
- CPU、内存、GPU、超时和文件需求；
- 可复现的最小测试样例。

不要把机理模型描述成自然语言黑盒。契约越明确，智能体选择参数和平台排障越可靠。

## 选择原则

先按任务质量、上下文长度、工具调用能力、部署位置和合规性筛选，再比较吞吐与成本。模型升级应通过新配置或可追踪版本完成，不要在生产配置中无记录地替换模型标识。
