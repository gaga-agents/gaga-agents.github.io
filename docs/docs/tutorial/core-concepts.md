# 核心概念

平台把一次智能体请求拆成可管理的对象。先理解对象边界，再学习页面操作和编排，排障时才能快速定位责任层。

## 对象关系

```text
用户 → 项目 → 智能体配置 → 会话 → 执行
                 ├─ LLM / 工具 / Skills / 知识库
                 └─ 记忆 / 规划 / Prompt / 执行策略
```

| 对象 | 作用 | 典型生命周期 |
| --- | --- | --- |
| 项目 | 资源、智能体、构建和权限的归属边界 | 创建 → 使用 → 归档 |
| 资源 | 可复用的模型、工具、Skill 或知识库 | 注册 → 验证 → 版本化 |
| 智能体配置 | 一组可执行的行为与依赖声明 | 草稿 → 调试 → 激活 → 归档 |
| 会话 | 某个用户与某个智能体的上下文容器 | 创建 → 交互 → 结束 |
| 执行 | 一次请求的步骤、工具调用和结果 | pending → running → success/failed |
| 事件 | 流式运行中的可观察事实 | start → step/tool → complete/error |

## 配置式智能体的六层

后端 `ConfigAgent` 将配置拆成 LLM、工具、记忆、规划、Prompt、执行策略，并可附加知识库配置。页面上修改一个字段，实际可能改变整个运行时的输入上下文或工具选择，因此建议一次只修改一个层级并重新验证。

## 什么时候使用哪个对象

- 想复用模型连接：创建 LLM 资源，而不是把连接字段复制到每个智能体。
- 想保留多轮上下文：创建会话并选择记忆策略。
- 想分析一次失败：查看执行记录和事件时间线，而不是只看最终答案。
- 想复用流程：创建编排定义或子流程，而不是在 Prompt 中描述所有步骤。
