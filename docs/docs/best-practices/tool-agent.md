# 构建工具型智能体

工具型智能体通过 Skills、API、代码或机理模型影响外部世界。设计重点是工具选择、参数契约、失败处理和副作用治理。

![工具型智能体示例](/img/screenshots/tool-agent.webp)

## 推荐流程

1. 把任务拆成“模型判断”和“确定性执行”两部分。
2. 为每个工具定义窄而明确的用途和 Schema。
3. 使用固定参数独立测试工具。
4. 只把必要工具授权给智能体。
5. 在调试轨迹中检查选择理由、参数和结果。
6. 对写操作增加幂等、确认、审批或回滚机制。

## 失败策略

- **参数错误**：返回字段级错误，让智能体修正一次；不要无限重试。
- **暂时不可用**：按幂等性和退避策略重试，并设置总超时。
- **业务拒绝**：把明确原因返回用户，不要换参数绕过权限。
- **部分成功**：记录已完成步骤和补偿方式，避免重复副作用。
- **代码执行失败**：保留沙箱日志，但不要向最终用户泄露凭据或内部路径。

## 验收问题

智能体是否会在无需工具时调用工具？是否能处理空结果？高风险动作是否需要明确确认？同一请求重试会不会产生重复写入？平台能否从任务 ID 追踪到外部调用？这些问题都通过后，工具型智能体才适合进入构建发布。
