# 构建多智能体应用

多智能体的价值来自职责和上下文隔离，而不是角色数量。只有当任务确实需要不同专业能力、并行处理、独立权限或可替换服务时，才值得增加智能体。

## 职责拆分

一个好的角色只对一种结果负责。例如“资料检索”“数据计算”“风险复核”“最终汇总”比“万能助手 A/B/C”更容易验证。每个角色都应有明确输入、结构化输出、允许使用的资源和完成标准。

## 逐层构建

1. 单独调通每个智能体。
2. 用固定输入验证上下游数据契约。
3. 先连接主成功路径。
4. 再增加条件、并行、循环和错误路径。
5. 对端到端样例记录节点结果和总成本。
6. 最后构建并发布版本。

## 成本与可靠性

每增加一个智能体，都可能增加模型调用、上下文复制、超时和失败点。并行可以降低墙钟时间，但不会自动降低 Token 成本。让确定性节点完成转换、校验和合并，把模型调用留给真正需要语义判断的步骤。

## 结束条件

循环协作必须设最大轮次、总超时和明确的完成信号。出现冲突时，应指定仲裁角色或确定性规则，而不是让智能体无限讨论。
