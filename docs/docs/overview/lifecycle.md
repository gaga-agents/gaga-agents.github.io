# 产品生命周期

平台用项目空间串联资源与执行过程。一个标准交付路径分为四个阶段、十二个关键动作。

![平台四阶段生命周期](/img/diagrams/platform-lifecycle.svg)

## 阶段 1：治理入口

1. 注册或登录平台。
2. 创建或选择项目。
3. 进入项目空间。

项目不是简单的文件夹，而是权限和资源归属边界。未选择项目时，不应创建依赖项目上下文的智能体资源。

**完成标志**：工作台显示当前项目，后续创建的资源都能关联到该项目。

## 阶段 2：基础资源

4. 配置 LLM 提供商与模型。
5. 注册机理模型。
6. 选择或创建云平台 Skills。
7. 导入外部通用 Skills。
8. 创建知识库并处理文档。

基础资源应先独立验证，再接入智能体。这样可以把“模型不可用”“工具参数错误”“知识未索引”等问题提前隔离。

**完成标志**：模型连接测试成功；所需工具可执行；知识库处于可检索状态。

## 阶段 3：智能体配置

9. 创建智能体。
10. 配置 Prompt、LLM、工具、知识库、记忆、规划策略和执行参数。

配置顺序建议遵循“角色与目标 → 模型 → 外部能力 → 状态与规划 → 运行约束”。不要在基础资源仍不可用时反复调整 Prompt。

**完成标志**：智能体配置完整，依赖资源均来自当前项目或明确授权的共享资源。

## 阶段 4：调试与部署

11. 在调试页使用代表性样例验证输入、输出、工具调用和知识召回。
12. 构建并部署可交付版本。

调试不是只看最终答案。还要检查执行轨迹、错误分支、Token/成本、超时以及资源访问是否符合预期。

**完成标志**：关键样例通过，构建记录可追踪，部署后健康检查正常。

## 什么时候进入多智能体编排

如果一个智能体已经能稳定完成一类职责，但任务需要多个专业角色、并行处理或明确的条件分支，再进入[多智能体编排](../orchestration/design.md)。不要用复杂工作流掩盖单个智能体尚未调通的问题。
