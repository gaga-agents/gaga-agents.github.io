# 配置智能体

智能体配置页将行为定义和资源依赖放在一起。建议按稳定顺序逐步增加能力，每增加一类依赖就运行对应测试。

## 推荐配置顺序

1. **基本信息**：名称表达职责，说明写清输入、输出和边界。
2. **模板**：选择接近任务的模板，或从空白开始。
3. **LLM**：选择已独立验证的模型配置。
4. **Prompt**：定义角色、目标、限制、步骤和输出结构。
5. **工具**：只开放任务确实需要且验证通过的 Skills。
6. **知识库**：绑定范围明确、召回质量已验证的知识库。
7. **记忆**：决定需要保留什么、保留多久、在哪个边界可见。
8. **规划**：根据任务选择 ReAct、Plan-and-Execute、Chain of Thought 或自定义策略。
9. **高级参数**：设置超时、迭代、模型参数和执行限制。

## Prompt 结构

一个可维护的 Prompt 通常包含：

```text
角色：你是谁，代表哪类专业职责。
目标：什么结果算完成。
输入：可以信任哪些字段，哪些只是用户陈述。
能力：可使用哪些知识和工具。
约束：禁止事项、权限边界、时间和成本限制。
过程：必要的检查、调用和失败处理。
输出：字段、格式、证据与不确定性表达。
```

## 规划策略怎么选

| 策略 | 适用任务 | 注意事项 |
| --- | --- | --- |
| ReAct | 需要边思考边调用工具 | 控制最大迭代，避免重复调用 |
| Plan-and-Execute | 可先拆分再逐步执行的复杂任务 | 计划过长时需要重新规划机制 |
| Chain of Thought | 需要内部逐步推理的任务 | 不应把隐含推理当作可审计证据 |
| 自定义 | 有明确领域步骤或控制策略 | 需要额外测试与维护责任 |

## 保存与变更

任何影响行为的模型、Prompt、工具、知识库和规划变更，都应在构建说明中可追踪。生产使用的智能体不要直接依赖正在频繁修改的资源版本。
