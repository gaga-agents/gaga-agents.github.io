# 智能体多模态输入

智能体多模态输入是指在同一条用户消息中同时提交文字和图片，让支持视觉能力的模型理解截图、照片、图表或扫描件。

图片的上传、引用、持久化与清理规则详见[文件工作区](./file-workspace.md)。

## 使用前提

开始前确认：

1. 已在模型管理中创建一个实际支持视觉输入的模型资源；
2. 该模型资源勾选了“支持多模态（Vision）”；
3. 智能体已选择该模型并保存配置。

如果切换了模型资源，重新打开或刷新调试页，确认输入区出现图片按钮。

## 在调试页发送图片

1. 打开智能体的“调试”页面并创建或选择一个会话。
2. 点击输入框旁的图片按钮。
3. 选择本地图片。前端接受浏览器识别为 `image/*` 的文件，单张图片必须小于 10 MB。
4. 如需多张图片，重复选择；发送前可以预览或移除图片。
5. 输入问题，例如“比较这两张截图中的差异”。
6. 点击发送。前端先将待发送图片上传到当前 Session 工作区，再提交结构化消息。
7. 在消息时间线、模型调用事件和最终回答中检查执行结果。

当前前端没有设置明确的图片张数上限，但模型供应商通常限制单次请求的图片数量、总请求体和视觉 Token。生产环境应根据所用模型增加统一的服务端限制，不应只依赖浏览器的 10 MB 校验。

## 消息结构

调试页不会把 Base64 图片直接写入会话消息。上传成功后，请求中的 `message_content` 使用工作区引用：

```json
{
  "input": "请解释这张架构图",
  "session_id": "<session-id>",
  "message_content": [
    {
      "type": "text",
      "text": "请解释这张架构图"
    },
    {
      "type": "image",
      "attachment": {
        "unique_filename": "architecture-a1b2c3d4.png",
        "filename": "architecture.png",
        "mime_type": "image/png",
        "file_size": 245760
      }
    }
  ]
}
```

## 图片如何到达模型

```text
选择图片
  ↓ 浏览器检查 image/*、单张 < 10 MB
上传到当前 Session workspace
  ↓ 返回 unique_filename、mime_type、file_size
消息持久化 type=image + attachment 引用
  ↓ 组装本轮上下文
运行时读取 workspace 图片
  ↓ 转成 image_url Data URL
LLM Service
  ├─ OpenAI-compatible：保留图文内容块
  └─ Ollama：拆成 content + images
```

这种设计避免把大段 Base64 写入 MongoDB 消息、执行记录和事件流。图片数据只在模型调用前临时读取和编码，持久化记录保留文件引用。

运行时会把路径限制在当前 Agent 和 Session 的工作区内，拒绝绝对路径和越界引用。解析文件后还会重新确认 MIME 类型属于 `image/*`。

## 会话、上下文与记忆

图片引用会作为用户消息的一部分进入 Session 时间线。后续轮次是否再次把这张图片发送给模型，取决于所选记忆策略和上下文预算：

- `full`、`sliding_window` 和 `buffer` 会在消息仍被选入上下文时保留结构化图片块；
- `summary` 在压缩旧消息时只提取文本内容，旧图片本身不会进入摘要；
- `none` 不应被用来期待跨轮图片记忆；
- 上下文预算目前按每张图片约 512 Token 做内部估算，这不是供应商最终计费值；
- 即使消息记录仍存在，工作区图片被删除或存储不可读时，运行时会丢弃该图片块。

因此，对图片中的关键事实需要跨较长对话保留时，应让智能体先生成文字结论并在后续对话中引用该结论，不要只依赖旧图片持续留在上下文窗口中。更完整的策略比较见[模型、上下文与记忆](../tutorial/model-context-memory.md)。

## 图片与工具调用

视觉模型可以先理解图片，再根据文字部分决定是否调用工具。但路由、计划和部分记忆逻辑属于纯文本控制链路，只会提取多模态消息中的 `text` 块，不会直接读取图片像素。

建议每次图片输入都附带明确文字，例如：

```text
读取截图中的错误信息，判断最可能的原因；如需查询运行日志，再调用日志工具。
```

只有图片而没有任务描述时，视觉模型仍可能回答，但工具选择和规划意图会更不稳定。

## 常见问题

### 看不到图片按钮

检查智能体选用的模型资源是否启用了 `supports_vision`，并确认智能体保存后重新加载了模型配置。该字段为 `false` 时，调试页不会显示图片入口。

### 旧图片在后续对话中失效

检查图片是否已从工作区删除、消息是否被窗口或 Token 预算淘汰。

### 图片请求过慢或 Token 成本异常

减少图片数量和分辨率，只提交与任务有关的裁剪区域，并查看供应商返回的 Usage。平台的上下文预算估算不等于供应商的视觉 Token 计算方式。

### 图片按钮能用，但调用返回供应商错误

`supports_vision` 不会验证模型能力。对照供应商要求检查模型名称、API 兼容格式、允许的 MIME、图片大小和 Base64/Data URL 支持情况。
