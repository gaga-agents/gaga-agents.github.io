# 运行时、上下文与记忆

Agent Runtime 负责把静态配置变成一次受控执行。它需要在上下文、记忆层和工作空间之间传递状态，同时维持用户、项目、智能体和会话四层隔离。

![Agent Runtime 与状态管理](/img/diagrams/runtime-state.svg)

## 三类状态载体

- **上下文**：当前请求和近期交互中模型立即需要的信息，容量有限。
- **记忆**：经过选择后保留的长期或阶段性信息，可在后续执行中检索。
- **工作空间**：执行产生的文件、中间结果和代码产物，适合大对象而不是直接塞入 Prompt。

## 四层隔离

| 边界 | 解决的问题 |
| --- | --- |
| 用户 | 谁发起任务，拥有哪些权限 |
| 项目 | 资源、数据与团队治理归属 |
| 智能体 | 不同角色和配置之间的状态隔离 |
| 会话 | 同一智能体不同任务之间的短期状态隔离 |

## 记忆设计原则

1. 只存后续任务确实需要的信息，不保存完整聊天副本作为“记忆”。
2. 给记忆设置来源、时间、作用域和更新规则。
3. 用户纠正信息时要能覆盖或失效旧记忆。
4. 敏感数据按最小权限访问，并设置生命周期。
5. 调试时区分“模型从当前上下文得到”与“从记忆召回得到”。

状态问题通常表现为答非所问、跨会话串数据或上下文越来越贵。排查时先确认四层标识，再检查记忆写入/召回，最后检查 Prompt 拼装。
