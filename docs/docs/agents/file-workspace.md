# 文件工作区

文件工作区为每个 Session 提供独立的文件目录，统一保存用户上传的附件和智能体生成的文件。它不仅用于图片输入，也用于代码执行、文档处理、机理模型文件参数和结果交付。

## 工作区边界

有状态 Session 的目录结构为：

```text
WORKSPACE_BASE_DIR/
  {agent_id}/
    {session_id}/
      conversation.md
      memory/
      workspace/
        用户上传和工具生成的文件
```

隔离关系如下：

- Agent 是第一层目录边界，不同智能体不共用文件；
- Session 是实际的工作边界，同一智能体的不同 Session 也不共用文件；
- 消息只保存文件引用，文件内容保存在当前 Session 的 `workspace/` 中；
- 工具只能通过当前运行绑定的工作区访问文件；
- Stateless 执行使用临时目录，请求完成后随 `TemporaryDirectory` 删除，不能作为跨请求文件存储。

工作区隔离依赖服务端根据已鉴权的 Agent 和 Session 构造路径。调用方不应直接提交其他 Session 的绝对路径。

## 上传、下载和删除

在智能体调试页中，可以从聊天区上传文件，并在“文件工作区”页签查看当前 Session 的文件。工作区支持：

- 上传文件；
- 递归展示工具生成的子目录和文件；
- 下载文件；
- 删除单个文件；
- 将已有文件引用到输入框。

上传时，平台保留原始显示名称，同时生成带 8 位随机后缀的存储名称，例如：

```text
report.pdf → report-646b2cc2.pdf
```

这样可以避免同名上传直接覆盖。工具生成的子目录会按实际相对路径展示。下载和删除使用 `unique_filename`，该值可能是根目录文件名，也可能是 `results/report.pdf` 这样的子目录路径。

读取和下载需要 Session 所有者或相应项目访问权限；当前删除接口只允许 Session 所有者操作。

## `@文件` 引用

在输入框输入 `/` 可以搜索当前工作区文件，选择后会插入：

```text
[文件: results/report.pdf]
```

这里的“引用”不是把文件内容复制进消息，而是让本轮执行知道用户指向哪个工作区文件。前端优先匹配完整相对路径，也兼容文件名和早期引用格式。

引用普通附件时，路径会进入执行上下文，模型可以让文件工具读取它；引用图片时，还会建立结构化图片引用。若一句话没有显式引用文件，部分调试流程可能仍将当前工作区文件作为可用文件索引提供给智能体，因此涉及多个同名或相似文件时应主动引用完整路径。

## 图片和普通附件

两类文件使用同一个工作区和文件接口，但进入模型的方式不同：

| 类型 | 消息中的表示 | 进入模型的方式 |
| --- | --- | --- |
| 图片 | 文本引用加结构化 `image` 块 | 调用模型前读取文件并临时转换为 OpenAI-compatible Data URL |
| 普通附件 | 文件路径引用 | 不会自动塞入模型上下文，由文件工具、Skill 或外部执行器按需读取 |

图片内容不会以 Base64 持久化到消息和执行记录中。如果图片已删除、路径越界或不可读，运行时会丢弃对应图片块。模型还必须实际支持 Vision，否则即使图片上传成功也不能正确理解。

普通 PDF、Word、Excel、CSV、TXT 和 Markdown 等文件通常通过内置文件工具读取或生成。上传成功不等于模型已经读取文件。

## 工具如何读取和生成文件

启用内置工具后，运行时会把当前 Session 的 `workspace_dir` 注入文件工具和外部 Skill：

1. 工作区文件索引加入运行上下文；
2. 模型使用相对路径调用 `list_workspace_files`、`get_file_info`、文件读取或文档处理工具；
3. 工具将输入路径解析并限制在当前工作区；
4. 工具生成的结果继续写回当前工作区；
5. 前端刷新文件列表后即可下载或再次引用结果。

代码或 Skill 运行时的当前目录也是 Session 工作区，且通过 `WORKSPACE_DIR` 提供目录位置。当前外部 Skill 脚本并不经过沙箱，因此只能加载可信 Skill，并结合人工确认控制有副作用的调用。

机理模型工具需要文件参数时，会读取工作区相对路径，将文件上传到 Scheduler 临时存储，再把参数替换为 `_file_id` 引用。MCP 和普通外部 API 是否能接收文件取决于其各自协议，不会自动获得本地文件内容。

## 持久化与容器重启

文件保存在 `WORKSPACE_BASE_DIR` 指向的本地文件系统。容器重启后是否保留，取决于该目录是否挂载持久卷：

- 本地开发：目录位于宿主机或项目外部的持久路径时可保留；
- Docker：必须把实际的 `WORKSPACE_BASE_DIR` 挂载到 volume；
- Kubernetes：必须将同一路径挂载到 PVC；
- 未挂载时：文件跟随容器可写层，Pod 重建后可能丢失。

:::warning 路径配置必须一致

代码默认使用 `/app/workspaces`，而当前 Kubernetes 清单把 PVC 挂载到 `/workspace`。部署时必须显式设置 `WORKSPACE_BASE_DIR=/workspace`，或将卷挂载到 `/app/workspaces`；否则文件仍会写入未持久化的默认目录。
:::

数据库中的 Session 和消息记录不包含文件正文。只恢复 MongoDB 而没有恢复工作区卷，会留下无法读取的文件引用。

## 多副本部署

多个 agents-management 实例必须看到同一个 `WORKSPACE_BASE_DIR`，否则上传请求和后续执行落到不同实例时会出现“文件不存在”。可选方案包括：

- 使用支持 `ReadWriteMany` 的共享文件系统；
- 将工作区改造为对象存储，并通过统一存储接口访问；
- 单副本运行作为临时方案，但不能提供水平扩展和故障切换。

## 路径安全

下载、删除、图片解析和工具读取都会解析规范化路径，并检查最终路径仍位于当前 Session 工作区。绝对路径、盘符路径和通过 `..` 越界的路径不应被接受。

部署和工具开发还应遵循：

- 对外只暴露工作区相对路径，不返回真实服务器路径；
- 不让模型构造绝对路径或伪造内部文件 ID；
- 文件名只用于展示，读写以服务端解析后的安全路径为准；
- 解压缩时防止 Zip Slip，并限制解压后的文件数和总体积；
- 工具创建子目录时仍需执行同样的根目录校验；
- 隐藏以 `.` 开头的内部目录，避免把索引和 Skill 文件展示为用户附件。

## 大小、类型和配额

当前上传接口会一次性把整个文件读入内存，代码中没有统一的单文件大小、文件类型、Session 总容量或文件数量限制。因此生产环境必须在网关和应用层补充限制，例如：

- 请求体和单文件大小上限；
- 允许或禁止的 MIME 类型与扩展名；
- 每个用户、项目、Agent 和 Session 的容量配额；
- 图片像素、压缩包展开体积和文档页数限制；
- 恶意文件扫描，以及可执行脚本的额外权限控制。

仅检查扩展名不足以判断真实文件类型。应用层应同时检查 MIME、文件特征和实际解析结果，并在超限时返回明确的 `4xx` 错误。
