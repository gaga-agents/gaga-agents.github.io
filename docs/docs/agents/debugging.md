# 调试与评估

智能体调试的目标不是得到一次“看起来不错”的回答，而是证明它在代表性输入和失败条件下仍能按约束工作。

## 建立最小测试集

至少覆盖：

- 正常输入；
- 缺少关键字段；
- 歧义或冲突信息；
- 空知识结果；
- 工具失败或超时；
- 权限不足；
- 超长输入和最大迭代；
- 要求绕过规则的对抗输入。

## 按层排查

1. **输入层**：项目、用户、会话和变量是否正确。
2. **配置层**：模型、Prompt、工具、知识库和规划版本是否符合预期。
3. **检索层**：召回了什么，重排后证据是否相关。
4. **工具层**：模型为何选择该工具，参数是否通过 Schema 校验。
5. **执行层**：节点耗时、重试、异常和终止原因。
6. **输出层**：结果是否满足结构、证据和风险要求。

## 评价维度

| 维度 | 问题 |
| --- | --- |
| 任务完成度 | 是否实现用户目标，而非只生成流畅文本 |
| 事实与证据 | 结论是否被知识或工具结果支持 |
| 工具正确性 | 是否选择正确工具并传入有效参数 |
| 稳定性 | 相同任务多次执行是否在可接受范围内 |
| 效率 | Token、调用次数和耗时是否合理 |
| 安全性 | 是否越权、泄露信息或执行高风险副作用 |

调试完成后保存失败样例和预期行为。后续更换模型、Prompt、知识或工具时，使用同一组样例回归，而不是凭印象判断。

平台的事件坐标、工具确认和执行状态见[运行时契约](../reference/contracts.md)，完整的评测—追踪闭环见[评测、追踪与回归](../features/evaluation-tracing.md)。
