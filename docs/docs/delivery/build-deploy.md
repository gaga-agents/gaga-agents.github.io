# 构建、发布与回滚

构建把可编辑配置冻结为可追踪的交付版本。发布则把该版本部署到目标运行环境。二者应分开：构建成功不代表生产环境健康，生产回滚也不应依赖重新编辑配置。

本页说明通用交付流程；Builder 的运行模式、资源固化、代码生成、状态与排障详见[智能体构建](./agent-build.md)。

## 构建前门槛

- 代表性测试集通过；
- 依赖的模型、Skills、知识库和子智能体版本明确；
- 超时、最大迭代和资源限制已设置；
- 高风险工具权限和审批路径已确认；
- 版本说明能够解释本次行为变化。

## 交付流程

1. 在 **智能体构建** 或编排构建入口选择目标配置。
2. 填写语义清楚的版本号/说明和变更摘要。
3. 生成构建产物并保留构建日志。
4. 部署到测试环境，执行冒烟测试和关键回归样例。
5. 通过后提升到生产环境，并持续观察错误率、延迟和成本。

## 版本应冻结什么

至少记录或锁定：智能体/编排定义、Prompt、模型标识与关键参数、工具 Schema、知识库版本或索引时间、运行时版本和镜像摘要。仅记录一个“v2”标签不足以复现行为。

## 回滚

发布前要保留上一个已知稳定版本及其依赖。回滚后验证 Gateway 路由、服务健康、模型连接、知识索引和工具权限，不能只看 Pod 是否恢复。
